## 下载与启动

1. 绿色 **Code → Download ZIP**，完整解压。
2. 安装 Python 3.10+（包含 Tcl/Tk；Windows 勾选 Add Python to PATH）。
3. Windows 双击 `start_windows.bat`；Mac/Linux 运行 `bash start_mac_linux.sh`。
4. 点击“导入内置素材”，配置并完成“YouTube 官方授权”。
5. 点击“扫描频道已上传视频”，选择剧集并核实匹配视频。
6. 核对界面所选视频、标题、封面、代码和时间，点击“发布（按所选时间定时公开）”。无需额外审核或批准弹窗。

多条匹配或无匹配不自动决定，可以在下拉框选择，或直接输入视频 ID。不会根据题材猜测英语标题对应的中文剧名。默认仅处理私密视频；YouTube 要求定时发布的视频从未公开过，程序不能从 API 完整判断历史，平台可能拒绝。

## Windows 连接超时 / WinError 10060

本机浏览器能访问 YouTube，不代表 Python 已走同一个代理。本版 config.json 已按本次提供的本机代理预设 http://127.0.0.1:7897，连接超时 30 秒；示例配置保留空代理以便其他机器自行设置。

1. 保持 VPN/代理客户端运行，确认本机 HTTP 或 Mixed 代理端口为 7897。
2. 在程序顶部检查“程序代理”为 http://127.0.0.1:7897，点“保存网络设置”。
3. 点击“诊断连接”，读取 Google OAuth、YouTube API 和程序传输层的结果。诊断不读取视频、不修改任何内容，也不显示令牌。
4. 收到 HTTP 400/401/403 等响应只表示收到网络响应，不证明账号授权或配额正常。扫描时的具体 HTTP 401/403 仍需排查授权、API 启用和配额；超时则继续检查代理端口、规则和系统防火墙。
5. 诊断后再次点击“扫描频道已上传视频”。日志实时显示正在核对频道、列表页数和视频详情批次。

如果 7897 是纯 SOCKS5 端口，可将代理改为 socks5h://127.0.0.1:7897；协议应与代理客户端提供的端口类型一致。端口未运行、协议不匹配或代理规则拒绝 Google 时，单纯延长超时不能解决。

本版让 OAuth 令牌刷新和 YouTube API 使用一致的显式代理；保持 TLS 验证。只读 API 请求有有限重试，实际修改不自动重试。测试覆盖配置与传输设置，但无法代替在你电脑上实际诊断代理。

更新时请备份旧目录，解压到新目录，把自己本机的 client_secret.json 与 token.json 复制到新目录。不要把这两个文件上传到 GitHub。config.json 的网络设置可在界面修改，local_work 中已批准记录如需迁移请备份；已变更的审核单仍须重新批准。


## 授权频道不匹配

出现 OAuth account/channel does not match configured channel_id 或“授权频道不匹配”，表示已收到 YouTube 响应，但当前 OAuth 返回的频道不是目标频道。目标 ID 保持 UC0koaDPTujsoVj-Tw27J0Qg，不应为了绕过检查随意改成个人频道。

1. 点击“切换授权频道”（或终端 python run.py auth --reauth），在 Google 页面重新选择账号并确认权限。
2. 同一 Google 登录账号可能有个人频道和多个品牌频道。如页面出现频道列表，选择 Supreme Hero Flicks 对应的品牌频道。
3. 可在 YouTube 右上角头像 → 切换账号确认自己能进入目标频道，再打开 https://www.youtube.com/account_advanced 查看当前频道 ID。这里用于核实身份；仅在网页切换账号不会替换程序已缓存的授权，因此仍需“切换授权频道”。
4. 若目标频道不在授权选择中，核实登录账号是否为频道所有者或受支持的品牌账号管理身份。仅有 YouTube Studio 邀请权限的账号可能无法通过 YouTube API 管理该频道，需要由频道所有者确认。
5. 新版日志显示“目标频道”和“本次授权返回的频道”名称及 ID。仍不匹配时，只需提供这些名称和 ID，不要发送 token.json、client_secret.json 或授权回调地址。

频道匹配成功后才写入新 token.json。选错频道不会覆盖此前保存的令牌，也不会修改频道或视频。切换账号不会更改排片或目标频道配置。

## “YouTube result differs from approved changes” 结果核对

此提示发生在提交后读取核对阶段，不能直接认定所有修改失败。请先在 Studio 核实，不要反复应用，也不要立即删除执行状态。

新版增加“核对线上结果（只读）”：选择该任务后点击，读取当前标题、说明、状态及发布时间并与已有审核单比较，不设置封面、不修改视频。等价命令：

```bash
python run.py verify --job 对应任务ID
```

核对报告保存在 local_work/任务ID/verification.json，包括差异字段、审核值和返回值。报告可能含私密视频说明，只在本机保存；排查时优先提供“差异字段”及相关时间，不要公开整份报告或令牌。

核对允许相同时间点的不同时区表示、标签顺序变化、语言标签大小写及空标签省略。YouTube 新增的未请求默认字段会单独记录，不作为原字段被改动的证据。已审核的标题和说明仍严格比较，缺失或不一致的需保留字段仍阻止确认。最多追加两次只读查询，等待短暂同步；不会重新提交修改。

收到“标题、说明及排期已核对一致”仅表示这些元数据已确认，实际封面需在 Studio 目视核实。若仍不一致，会显示具体字段，不会忽略真正的内容差异。若发布后已转成 public，原先 private 定时审核单也可能不再一致，请在 Studio 根据实际发布时间判断，不要为了通过核对把视频改回私密。

更新后要核对原任务，请在备份旧目录后把本机的 client_secret.json、token.json 和 local_work 文件夹复制到新目录，保留原审核单。然后仅点击“核对线上结果”，不需要再次批准或应用。若需要修正真实偏差，应重新读取、生成审核单、由你批准后执行。


## 简化发布模式（当前桌面入口）

按用户最新要求，原“审核→批准→应用”三个按钮合并为“发布（按所选时间定时公开）”。界面选择内容可直接查看，点击该按钮即授权程序执行该次所选变更，不额外弹出确认。后台保留执行快照用于冲突检查、差异诊断和防重复，不代表还要手动审批。

命令行同等入口为 python run.py publish --job 任务ID --video-id 已上传视频ID --title 1 --cover 1，可加 --code 和 --publish-local。之前的 review/approve/apply 命令保留作为可选高级操作，不是桌面发布的必经步骤。

无匹配、多匹配、频道不一致、版本冲突、时间过期或不确定执行结果仍会停止，这些是缺少正确目标或参数，不是额外审核次数。发布按钮不会上传新视频。
